# Telegram Bot UI/UX Design Guidelines

Этот навык (skill) определяет стандарты проектирования профессиональных, интуитивно понятных и визуально привлекательных пользовательских интерфейсов для Telegram-ботов. Разделы основаны на лучших практиках проектирования диалоговых систем (Conversational UX) и технической реализации через API Telegram.

---

## 1. Концепция разметки (Formatting System)

Для обеспечения максимальной совместимости и защиты от сбоев (вызванных неэкранированными символами `.`, `_`, `-` в динамических данных) в качестве основного режима парсинга текста используется **HTML** (`parse_mode: "HTML"`).

### Оформление шрифтов:
*   **Заголовки блоков:** `<b>ЗАГОЛОВОК СЕКЦИИ</b>` (заглавные полужирные буквы).
*   **Вводные/Инструкции:** `<i>Курсивный текст подсказок и описания шагов.</i>`
*   **Данные для копирования:** `<code>моноширинный текст</code>` (ID сессий, ссылки, пароли, адреса, даты).
*   **Списки и логи:** `<pre>блочный моноширинный формат для текстовых вырезок, логов или кодов ошибок</pre>`.

---

## 2. Разделители и визуальная иерархия

Для структурирования сообщений и отделения метаданных используются элементы псевдографики:

*   `🤖 <b>[Название Бота]</b> • [Раздел]` — Стандартный заголовок любого сообщения.
*   `━━━━━━━━━━━━━━━━━━━━━━` — Горизонтальная линия-разделитель (длина: 22-26 символов).
*   `├` — Параметр или пункт меню в середине списка.
*   `└` — Последний параметр или пункт в завершении списка.
*   `▪` — Маркер списка возможностей или инструкций.

## 3. Архитектура диалоговых окон (Message Layouts)

### А. Панель мониторинга / Дашборд сессии
Применяется при отслеживании длительного или активного процесса (например, запись, скачивание):
```html
🔴 <b>СТАТУС: ЗАПИСЬ АКТИВНА</b>
━━━━━━━━━━━━━━━━━━━━━━
⏳ <i>Ассистент находится в комнате и записывает аудиопоток.</i>

<b>Информация о сессии:</b>
├ 🆔 Идентификатор: <code>meeting_987654</code>
├ 👤 Отображаемое имя: <b>Бот-Ассистент</b>
└ 📅 Запуск: <code>20.06.2026 16:15 (МСК)</code>

<i>Используйте кнопки ниже для управления текущей сессией.</i>
```

### Б. Карточка результата (Сводные отчеты)
Применяется для вывода готовой аналитики или данных:
```html
📝 <b>ТРАНСКРИБАЦИЯ ГОТОВА</b>
━━━━━━━━━━━━━━━━━━━━━━
✅ Расшифровка разговора завершена и сохранена в базу.

<b>Сводная информация:</b>
├ 📋 Название: <b>Еженедельный созвон</b>
├ 👥 Участники: <code>3 спикера</code>
├ 💬 Объем данных: <code>142 реплики</code>
└ ☁️ Облако: <a href="https://disk.yandex.ru/client/disk/Recordings">Открыть на Яндекс.Диске</a>

📖 <b>Начало беседы:</b>
<pre>Иванов: Коллеги, начнем планерку...
Петров: Да, по первому вопросу все готово.</pre>
```

### В. Отчет о критическом сбое (Error Logs)
Применяется при возникновении исключений:
```html
❌ <b>СИСТЕМНЫЙ СБОЙ</b>
━━━━━━━━━━━━━━━━━━━━━━
Не удалось завершить операцию транскрибации.

⚠️ <b>Детали ошибки:</b>
<code>Error: OpenAI API - Bad Request (Invalid Token)</code>

<i>Попробуйте повторить запрос позже или проверьте настройки интеграции в меню.</i>
```

## 4. Сетки клавиатур и навигация (Keyboard UX)

1.  **Главные меню (Reply Keyboard):**
    *   Кнопки должны быть сгруппированы логически. Никогда не размещайте более 2 кнопок в одной строке (для удобства нажатия на мобильных устройствах).
    *   Всегда передавайте параметр `"resize_keyboard": true` (уменьшает кнопки до высоты текста).
    *   Всегда добавляйте во все подменю кнопку `🔙 Назад` или `🏠 В меню` для исключения тупиков навигации.
2.  **Действия под сообщениями (Inline Keyboard):**
    *   Используются для действий, привязанных к конкретному объекту (остановка записи конкретной встречи, выбор страницы в списке, генерация саммари по конкретному ID).
    *   Ограничение `callback_data` — строго **до 64 байт**. Формат: `[action]_[id]` (например, `stop_552123`).
3.  **Пошаговый сбор данных (Force Reply):**
    *   Для запроса ввода текстовых параметров (имя бота, пароль) бот отправляет сообщение с параметром `"force_reply": true` и `"selective": true`. Это автоматически открывает у пользователя окно ввода-ответа именно на это сообщение бота.

## 5. Типичные UX-ошибки (Anti-patterns)

*   **⚠️ Перегрузка текстом:** Отправка полных транскриптов встреч прямо в чат. Решение: обрезать текст до 1500 символов, вставляя троеточие, и прикладывать ссылку на файл/документ.
*   **⚠️ Отсутствие обратной связи:** Долгие расчеты ИИ без отправки промежуточного сообщения. Решение: отправлять статус `⏳ Обрабатываем данные...` сразу после получения запроса, а затем изменять сообщение методом `editMessageText` на результат.
*   **⚠️ Неэкранированные спецсимволы:** Падение бота на именах файлов с дефисами или точками в Markdown. Решение: Строгий переход на HTML.

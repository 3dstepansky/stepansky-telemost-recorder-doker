# Задачи: [НАЗВАНИЕ ФИЧИ]

**Входные данные**: Проектные документы из `/specs/[###-feature-name]/`

**Предварительные требования**: plan.md (обязательно), spec.md (обязательно для пользовательских историй), research.md, data-model.md, contracts/

**Тесты**: Приведенные ниже примеры включают тестовые задачи. Тесты являются НЕОБЯЗАТЕЛЬНЫМИ — включайте их только в том случае, если это явно запрошено в спецификации требований.

**Организация**: Задачи сгруппированы по пользовательским историям (User Stories) для возможности независимой реализации и тестирования каждой истории.

## Формат: `[ID] [P?] [Story] Описание`

- **[P]**: Может выполняться параллельно (разные файлы, нет зависимостей)
- **[Story]**: К какой пользовательской истории относится задача (например, US1, US2, US3)
- Указывайте точные пути к файлам в описании

## Соглашения по путям к файлам

- **Одиночный проект**: `src/`, `tests/` в корне репозитория
- **Веб-приложение**: `backend/src/`, `frontend/src/`
- **Мобильное приложение**: `api/src/`, `ios/src/` или `android/src/`
- Пути, показанные ниже, предполагают одиночный проект — скорректируйте их на основе структуры из plan.md

## Зависимости и порядок выполнения

### Зависимости фаз

- **Настройка (Фаза 1)**: Нет зависимостей — можно начинать сразу
- **Базовая часть (Фаза 2)**: Зависит от завершения Настройки — БЛОКИРУЕТ все пользовательские истории
- **Пользовательские истории (Фаза 3+)**: Зависят от завершения Базовой фазы
  - Пользовательские истории могут выполняться параллельно (при наличии ресурсов)
  - Или последовательно в порядке приоритета (P1 → P2 → P3)
- **Полировка (Финальная фаза)**: Зависит от завершения всех выбранных пользовательских историй

### Зависимости пользовательских историй

- **Пользовательская история 1 (P1)**: Можно начинать после завершения Базовой фазы (Фаза 2) — нет зависимостей от других историй
- **Пользовательская история 2 (P2)**: Можно начинать после завершения Базовой фазы (Фаза 2) — может интегрироваться с US1, но должна тестироваться независимо
- **Пользовательская история 3 (P3)**: Можно начинать после завершения Базовой фазы (Фаза 2) — может интегрироваться с US1/US2, но должна тестироваться независимо

### Внутри каждой пользовательской истории

- Тесты (если включены) ДОЛЖНЫ быть написаны и падать (FAIL) до начала реализации
- Модели перед сервисами
- Сервисы перед эндпоинтами
- Базовая реализация перед интеграцией
- История должна быть завершена перед переходом к следующему приоритету

### Возможности параллельной работы

- Все задачи Настройки, помеченные [P], могут выполняться параллельно
- Все базовые задачи, помеченные [P], могут выполняться параллельно (в рамках Фазы 2)
- После завершения базовой фазы все пользовательские истории могут быть начаты параллельно (если позволяет команда)
- Все тесты для пользовательской истории, помеченные [P], могут выполняться параллельно
- Модели внутри истории, помеченные [P], могут разрабатываться параллельно
- Разные пользовательские истории могут выполняться параллельно разными разработчиками

## Стратегия реализации

### Сначала MVP (Только Пользовательская история 1)

1. Завершить Фазу 1: Настройка
2. Завершить Фазу 2: Базовая часть (КРИТИЧНО — блокирует все истории)
3. Завершить Фазу 3: Пользовательская история 1
4. **ОСТАНОВИТЬСЯ И ПРОВЕРИТЬ**: Протестировать Пользовательскую историю 1 независимо
5. Развернуть/продемонстрировать при готовности

### Инкрементная поставка

1. Завершить Настройку + Базовую часть → База готова
2. Добавить Пользовательскую историю 1 → Протестировать независимо → Деплой/Демо (MVP!)
3. Добавить Пользовательскую историю 2 → Протестировать независимо → Деплой/Демо
4. Добавить Пользовательскую историю 3 → Протестировать независимо → Деплой/Демо
5. Каждая история добавляет ценность без нарушения работы предыдущих историй

### Командная стратегия параллельной работы

При наличии нескольких разработчиков:

1. Команда вместе завершает Настройку + Базовую фазу
2. Как только Базовая фаза завершена:
   - Разработчик А: Пользовательская история 1
   - Разработчик Б: Пользовательская история 2
   - Разработчик В: Пользовательская история 3
3. Истории завершаются и интегрируются независимо

## Заметки

- Задачи [P] = разные файлы, нет зависимостей
- Метка [Story] связывает задачу с конкретной пользовательской историей для отслеживания
- Каждая история должна быть независимо завершаемой и тестируемой
- Убедитесь, что тесты падают до реализации
- Делайте коммит после каждой задачи или логической группы
- Останавливайтесь на любой контрольной точке для проверки истории независимо
- Избегайте: расплывчатых задач, конфликтов в одном файле, кросс-историйных зависимостей, нарушающих независимость

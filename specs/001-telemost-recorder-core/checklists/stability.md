## Валидация стабильности и обработки сбоев

- [x] **CHK001**: Определено ли поведение при сбое основного API транскрибации (AssemblyAI)? *(Да, переключение на Groq Whisper в FR-012).*
- [x] **CHK002**: Определен ли способ обхода ограничений на размер файла в резервном Groq Whisper API (25 МБ)? *(Да, нарезка FFmpeg на 10-минутные чанки без перекодирования в FR-013).*
- [x] **CHK003**: Предусмотрена ли защита от утечек ресурсов и зависших Chromium процессов на сервере при аварийной остановке контейнера? *(Да, в FR-009 и User Story 2).*
- [x] **CHK004**: Установлено ли поведение системы при отсутствии активности участников (тишина во время встречи)? *(Да, описано в разделе "Граничные случаи").*

## Валидация управления ресурсами хост-сервера

- [x] **CHK005**: Описана ли автоматическая очистка временных аудиофайлов и чанков на диске хост-сервера после успешной сессии? *(Да, в FR-017).*
- [x] **CHK006**: Предусмотрен ли таймаут простоя для отключения бота из пустой комнаты (для экономии CPU/RAM)? *(Да, в FR-007).*
- [x] **CHK007**: Ограничено ли максимальное время записи одной конференции для защиты диска хост-сервера? *(Да, лимит 180 минут в FR-008).*

## Валидация безопасности и изоляции

- [x] **CHK008**: Гарантирована ли изоляция учетных данных Яндекс.Диска пользователей от кода контейнера? *(Да, данные передаются динамически через API/n8n).*
- [x] **CHK009**: Изолирован ли запуск независимых встреч для разных пользователей? *(Да, через уникальные имена контейнеров `telemost_<chat_id>` в User Story 5).*

## Валидация перспективных фич (Архив, RAG, Лайв-агент)

- [x] **CHK010**: Зафиксированы ли меры безопасности для исключения утечек векторных данных между пользователями? *(Да, в принципе RAG Privacy в Конституции и FR-036).*
- [x] **CHK011**: Определен ли способ обхода лимитов контекстного окна LLM при мульти-документном RAG-поиске? *(Да, в исследовательском подразделе 9.3 описаны методы Top-K и Map-Reduce).*
